Three product-safe ways to reorder event columns in the scheduling sheet. The data below mirrors the current header pattern: column name, linked event chip, delete affordance, and an add-column slot.

Current recommendation Option A: drag handle, with Option B commands as accessible fallback.

Option A: drag handle in each column header

Best for admins who think spatially. The handle makes the draggable target explicit while preserving double-click rename and delete.

fastest daily use needs keyboard fallback

Option B: column menu with move commands

Most accessible and least surprising. Better for infrequent reorders, but slower when moving several columns across the sheet.

Option C: explicit reorder mode with apply/cancel

Safest for high-consequence sheets. Reorder cards in a lane, preview the resulting table, then apply. This avoids accidental structure changes.

What I would spec

Persist an ordered columns[] array. Reorder changes only array position, not column ids or cell keys, so existing cell data remains stable.

Safety behavior

Delete stays a separate two-click action. Dragging should never trigger rename, delete, link refresh, or cell editing.

Accessibility baseline

Even if drag is approved, include menu actions: move left, move right, move to start, move to end. That gives keyboard and screen-reader users the same capability.
